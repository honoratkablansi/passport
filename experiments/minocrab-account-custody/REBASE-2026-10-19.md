# Compatibility after the 19 October rebase

This branch is rebased onto Passport main `fc7c24067a52b1343d2cb3f9889a0a297a750d60`
(the merge of #177). The frozen reference, Rust implementation, generated circuit
inputs and historical evidence remain unchanged.

The shared `contract/src/wallet/webauthn.ts` helper gained optional credential
creation settings (PRF, resident-key preference and RP display name) and a returned
PRF capability flag. Its signing and assertion-verification code is unchanged.
The native SDK adapter now permits that exact file hash in addition to its
original hash: `b49c26fcb9a405885e18c44e40e94b20ca7c2c18c638344557b7a5b18602c108`.
Every other pinned reference source and all 52 ZKIR hashes still have to match the frozen oracle.

Validation on 19 October:

- Frozen reference: all eight source hashes and 52 circuit hashes pass.
- Native SDK bridge: activation and inbox append match native/reference state and
  effects under k256, JubJub and P256 (six executions).
- P256 offline suite: high-S assertion, OpenSSL cross-implementation, binding
  negatives and device/grant/recovery simulation pass.
- Default contract TypeScript build passes.

These are offline compatibility checks using cached pinned generated artifacts.
The 112-transaction localnet run and benchmark receipts retain their original
source/executable hashes and dates; they were not rerun after this adapter edit.
This note does not claim new proving timings or new on-node coverage.

The localnet `/check` request also has a rule-specific scanner exception for its
fixed `127.0.0.1` HTTP endpoint. This is a comment-only change to the laboratory
harness; it does not change request behavior or historical evidence hashes.
